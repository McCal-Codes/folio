# Folio 0.6.9.2: two crashes fixed

DRAFT, 17 Nov 2026. A hotfix on 0.6.9.1 (REL-12), cut from `hotfix/0.6.9.1`. The opening paragraph of the public release
notes is McCal's and is not written here (REL-25); the changelog lines in `[0.6.9.2]` are a first draft for the same reason.

## Why a hotfix (REL-4c)

Both crashes reach people on the stable build and are not fixed in any 0.6.9.x. REL-4c allows a hotfix branch only when a
migration is mid-flight on `main` or the bug is in the stable build's own update or supporter path. Neither holds here, so
this needs McCal's call and the `release-exception` label on its pull request. Neither fix touches an update or supporter
path, so REL-20 does not apply. The same two fixes go on `main` for the next beta (the padding one is already there,
`a7034c06`).

## What changed

- `FoldAvoidance.kt`: `FoldAvoidingBox` holds each animated padding at zero or more (`Dp.atLeastZero()`). The panel's
  spring (damping .9) dips below zero on its way back to the window's edge and `Modifier.padding` throws on a negative
  value. 8 crash files, a Flip3 and two other phones.
- `Focus.kt`: `FocusController.buildRule` builds the Android 15 modes rule inside `modernOrLegacy`, and falls back to the
  legacy `AutomaticZenRule(...)` constructor when any call in that chain throws. A Samsung Z Flip 3 on Android 15 reports API 35 but
  has no `AutomaticZenRule.Builder`, which threw NoSuchMethodError (an Error). Each Focus's body in `apply` also runs in
  `guardedZen`, so a Do Not Disturb failure never reaches the main thread; schedules and charging run the same path with no tap.
  The fallback rule has no device effects (dim wallpaper, grayscale, dark theme) on such a phone.

## Version

`folioVersion = "0.6.9.2"`, `versionCode` **6092**, above 0.6.9.1 (6091) and below the next feature release. The roadmap needs
nothing: a hotfix lives in its release's `0.6.9` section. The changelog's `[0.6.9.2]` is dated in this bump (REL-10).
