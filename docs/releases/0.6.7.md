# Folio 0.6.7: seven fixes

A small stable release built from `main`, two days after 0.6.6. Nothing new to learn: it fixes what people reported
on 0.6.5 and 0.6.6, plus what the Fold8 turned up here. `versionName` is `0.6.7`, `versionCode` is `607`, so it
installs over 0.6.6 like any update and Software Update offers it to everyone on 0.6.5 and 0.6.6.

(Planned as 0.6.6.1. Folio's `versionCode` is MAJOR × 10000 + MINOR × 100 + PATCH, so a four-part version has
nowhere to go; the fixes ship as 0.6.7 and the language-and-Home release that had that number is now 0.6.8.)

Everything in section 1 needs the release keystore, so only McCal can do it.

## 1. Build and sign it

One command. It reads the version out of `app/build.gradle.kts`, runs `:app:assembleRelease`, signs it, and writes
the APK, its checksum and the signing certificate into `dist/Folio-0.6.7/`.

```bash
FOLIO_RELEASE_STORE_FILE=/path/outside/the/repo/folio-release.jks FOLIO_RELEASE_STORE_PASSWORD=… FOLIO_RELEASE_KEY_ALIAS=… FOLIO_RELEASE_KEY_PASSWORD=… ./scripts/release-signed.sh
```

It refuses to overwrite an existing `dist/Folio-0.6.7/`, so delete that folder to build again.

| File | What it is |
|---|---|
| `Folio-0.6.7.apk` | the build, signed with the release key |
| `SHA256SUMS.txt` | the checksum to publish beside it |
| `signing-certificate.txt` | the certificate digest, so anyone can check a later build came from the same key |

It has to be the same key as 0.6.6. A build signed with anything else does not install over it, and Android's
message for that says almost nothing useful.

## 2. What's in it

Seven fixes, no new features, so the release notes are the changelog and nothing else needs explaining.

| What | Where it came from |
|---|---|
| Double tap on an empty spot works again | #61 |
| The dock steps aside for Today View | #25 |
| Icons follow a theme that changes them, plus Refresh Icons | #19 |
| No more smeared, doubled pages on Android's wallpaper | #12, #35 |
| The Preview bar no longer covers the App Library | found here, on the Fold8 |
| Every Settings page has a way back | found here, on the Fold8 |
| Home's background costs the GPU about a third less while swiping | measured here |

All seven are in [PR #81](https://github.com/McCal-Codes/folio/pull/81), with how each was reproduced and checked.

## 3. Before sending it

- Publish the SHA-256 next to the download, in whatever message carries the link.
- Run the APK through VirusTotal and link the report. A sideloaded launcher holding `REQUEST_INSTALL_PACKAGES`
  usually collects a heuristic flag or two from small engines; saying so up front reads better than letting someone
  find it.
- Point at [PERMISSIONS.md](../../PERMISSIONS.md). 0.6.7 asks for nothing 0.6.6 didn't.
- Supporter codes carry over untouched. Nothing about the Market, sources or Keyd changed in this build, so nobody
  has to redeem anything again.

## 4. What to ask people to try

The two worth a second pair of eyes, because neither has a regression test yet:

1. **Background › Android wallpaper, then swipe between pages.** This is #12/#35. On a phone that had the bug, it
   should be clean from the first swipe, folded and unfolded.
2. **Settings, unfolded and upright**, where the list isn't pinned: every page should have something that reads as a
   way back, not just the sidebar button.

Ask for the device, the screen it happened on, and the Folio version from Settings › What's New.
